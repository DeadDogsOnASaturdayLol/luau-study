SERVER SCRIPTSSEARCH: server script authoritative shared game rules damage currency saving NPC RemoteEvent OnServerEvent ServerScriptService security › 
WHAT IT IS:

A normal Script usually runs on the SERVER.

The server is the authority for shared gameplay. If something matters to the real game state — money, damage, shared doors, NPCs, round state, saving data — the server should usually be involved.

THINK OF IT LIKE:

SERVER SCRIPT
= the referee and shared world.

LOCAL SCRIPT
= one player's controller/screen.

COMMON USES:

-- damage validation
-- currency and rewards
-- shared world changes
-- NPC behavior
-- round systems
-- DataStores
-- receiving RemoteEvents
-- anti-exploit validation


PLAYER JOIN EXAMPLE:

local Players = game:GetService("Players")

    print(player.Name .. " joined")
end)

This works on the server because the server can see every Player joining.


REMOTE EVENT EXAMPLE:

remote.OnServerEvent:Connect(function(player, action)
    print(player.Name)
    print(action)
end)

The Player is automatically supplied FIRST by Roblox.


IMPORTANT SECURITY IDEA:

A client should REQUEST.
The server should VERIFY.

BAD:

remote.OnServerEvent:Connect(function(player, money)
    player.leaderstats.Money.Value += money
end)

A malicious client could ask for a ridiculous number.

BETTER:

remote.OnServerEvent:Connect(function(player, action)
    if action ~= "CollectCoin" then
        return
    end

    -- Server checks:
    -- Does the coin exist?
    -- Is the player close enough?
    -- Was it already collected?
end)

MODULE SCRIPTSSEARCH: modulescript module script require reusable function library config configuration return table ReplicatedStorage utility shared code › 
WHAT IT IS:

A ModuleScript stores reusable code that another script loads with require().

It normally RETURNS something — commonly a table containing functions or settings.


BASIC MODULE:

function module.sayHello(name)
    print("Hello " .. name)
end

return module


USING IT:

    require(game.ReplicatedStorage.MyModule)

CONFIG MODULE:

    WalkSpeed = 16,
    Damage = 25,
    Cooldown = 1
}

return Config


USING CONFIG:

    require(game.ReplicatedStorage.Config)

print(Config.Damage)


WHY USE MODULES?

WITHOUT A MODULE:

Script A copies damage code.
Script B copies damage code.
Script C copies damage code again.

WITH A MODULE:

Put the shared function in one place.
Every script requires the same module.


FUNCTION MODULE:

local module = {}

function module.damageHumanoid(humanoid, amount)
    if not humanoid then
        return
    end

    humanoid:TakeDamage(amount)
end

return module


CALL IT:

local DamageModule =
    require(game.ReplicatedStorage.DamageModule)

DamageModule.damageHumanoid(humanoid, 25)


IMPORTANT:

A ModuleScript is not automatically "server" or "client."

If a server Script requires it:
-- it runs in the server environment.

If a LocalScript requires it:
-- it runs in that client's environment.

ReplicatedStorage
-- when both server and client need access.

ServerScriptService / ServerStorage
-- for server-only modules.

    for _, other in Players:GetPlayers() do
        if other ~= player then
            local humanoid = other.Character and other.Character:FindFirstChildOfClass("Humanoid")
            if humanoid and humanoid.Health > 0 then
                table.insert(list, humanoid)
