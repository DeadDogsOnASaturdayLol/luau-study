WITHOUT A MODULE:

Script A copies damage code.
Script B copies damage code.
Script C copies damage code again.

WITH A MODULE:

Put the shared function in one place.
Every script requires the same module.


FUNCTION MODULE:

    if not humanoid then
        return
    end

    humanoid:TakeDamage(amount)

return module


CALL IT:

    require(game.ReplicatedStorage.DamageModule)

DamageModule.damageHumanoid(humanoid, 25)

WHAT IT IS:

A normal Script usually runs on the SERVER.

The server is the authority for shared gameplay. If something matters to the real game state — money, damage, shared doors, NPCs, round state, saving data — the server should usually be involved.

THINK OF IT LIKE:

SERVER SCRIPT
= the referee and shared world.

LOCAL SCRIPT
= one player's controller/screen.

COMMON USES:

-- damage validation
-- currency and rewards
-- shared world changes
-- NPC behavior
-- round systems
-- DataStores
-- receiving RemoteEvents
-- anti-exploit validation

    print(player.Name .. " joined")

    print(player.Name)
    print(action)
end)

The Player is automatically supplied FIRST by Roblox.

A client should REQUEST.
The server should VERIFY.

BAD:

    player.leaderstats.Money.Value += money

        return

    -- Server checks:
    -- Does the coin exist?
    -- Is the player close enough?
    -- Was it already collected?

DEEPER NOTES

GETSERVICE PATTERNSEARCH: getservice service game players replicatedstorage tweenservice runservice › 
Most Roblox services are retrieved like this:

local Players = game:GetService("Players")
local TweenService = game:GetService("TweenService")

Why GetService?
• It clearly says you are retrieving a Roblox service.
• It works even for services you do not normally access as game.ServiceName.
• It is the normal reusable pattern for service variables.

A service is usually a singleton system owned by Roblox rather than an object
you create with Instance.new().

DEEPER NOTES
game is the DataModel at the root of an experience. GetService() asks that DataModel for one of Roblox's service singletons. Store the result in a local variable once and reuse it instead of repeatedly looking it up.

COMMON PATTERN
local Players = game:GetService("Players")
local ReplicatedStorage = game:GetService("ReplicatedStorage")

WHERE IT MATTERS
Some services are replicated, some are server-only, some expose client-only behavior, and some only exist for Studio/plugin code. Getting a service does not automatically mean every member on that service can be used from every script type.

COMMON MISTAKE
Typing TweenService:Create(...) without ever defining TweenService. Unless some other code created that variable, you normally need the GetService line first.

RemoteFunctionSEARCH: remotefunction invokeserver onserverinvoke invokeclient callback request response › 
Request/response networking.

Client:
local result = RemoteFunction:InvokeServer(...)

Server:

    return result
end

Unlike RemoteEvents, RemoteFunction callbacks are assignments, not

DEEPER NOTES
RemoteFunction is request/response networking. InvokeServer() waits for the server callback to return a value. OnServerInvoke is assigned a function rather than connected with :Connect().

WHEN TO USE
When the caller truly needs a reply before it can continue, such as requesting a small authoritative snapshot.

Because the caller waits, unnecessary chains of remote invocation can create stalls. Be especially careful with server -> client InvokeClient() because the client can disconnect, error, or fail to return.

RULE OF THUMB
Use RemoteEvent for most messages; use RemoteFunction when the synchronous response is actually required.

local Players = game:GetService("Players")
local module = {}

function module.isAlive(humanoid)
    return humanoid ~= nil and humanoid.Health > 0
end

function module.clampDamage(amount)
    return math.clamp(tonumber(amount) or 0, 0, 50)
end

function module.canDamage(attackerPlayer, targetHumanoid)
    if not module.isAlive(targetHumanoid) then
        return false
    end

    local targetPlayer = Players:GetPlayerFromCharacter(targetHumanoid.Parent)
    return targetPlayer ~= attackerPlayer
end

function module.applyDamage(attackerPlayer, targetHumanoid, amount)
    if not module.canDamage(attackerPlayer, targetHumanoid) then
        return false
    end

    local damage = module.clampDamage(amount)
    if damage <= 0 then return false end

    targetHumanoid:TakeDamage(damage)
    return true
